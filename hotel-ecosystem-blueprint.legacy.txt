BID rules:

- globally unique
- immutable
- property-aware
- human-readable
- concurrency-safe
- searchable
- staff-visible
- customer-visible
- not based on reservations.id
- not based on OTA reference
- booking source is not embedded into BID

Date segment:

uses property local date.

For OAK Lawang:

Asia/Jakarta

Collision handling:

1. Generate suffix.
2. Attempt insert.
3. UNIQUE(bid) is authoritative.
4. On conflict regenerate.
5. Retry bounded number of times.
6. Fail hard when retry limit exhausted.

================================================================================

BEGIN
↓
LOCK BOOKING FOR UPDATE
↓
LOCK ALL CHILD RESERVATIONS FOR UPDATE
↓
PRE-VALIDATE ALL CHILDREN
↓
LOCK AVAILABILITY ROWS FOR UPDATE
↓
VALIDATE INVENTORY OWNERSHIP
↓
RELEASE INVENTORY
↓
CANCEL CHILD RESERVATIONS
↓
WRITE RESERVATION AUDITS
↓
UPDATE PARENT BOOKING
↓
WRITE BOOKING AUDIT
↓
OUTBOX EVENT                   [TARGET]
↓
COMMIT

Any failure:

ROLLBACK ALL

Rules:

BOOKED
→ cancellable

CANCELLED
→ idempotent no-op

→ cancellation rejected

CHECKED_OUT
→ cancellation rejected
